ARCHITECTURAL DECISION RECORDS WITH JUSTIFICATION
ADR-001 Web React+TypeScript with Vite, Firebase Hosting. Accepted. Against Flutter Web: React closer to normal DOM, lower build/runtime burden for content-heavy dashboard and browser accessibility; Flutter unified future mobile code but currently unnecessary. Against Firebase App Hosting Next.js: SSR/SEO not vital to a signed-in dashboard; App Hosting adds SSR/build complexity. Revisit if public SEO/site generation critical.
ADR-002 PWA optional. Accepted. HTML install manifest and service worker later; avoid user-data caching offline, do not imply universal iOS push. Revisit if actual residents/collection workers require offline capture and permissions are addressed.
ADR-003 Gemini via Google Agent Platform/Vertex hosted server side. Accepted as proposal. Against direct browser Gemini API: server enforces spend, partner credentials, audit and role authorization. Gemini Flash as first candidate; Pro escalation only if benchmarks justify; actual model IDs verify in project.
ADR-004 ADK single coordinator with typed tools instead of many agents. Accepted provisional. Against multi-agent parallel fleet: latency/tool unpredictability and cost, obscures accountability. Revisit only after gold test case results identify advantage.
ADR-005 Cloud Run trusted backend, Firestore canonical tenant-scoped versioned state. Accepted. Against using Memory Bank/vector search for stock: semantic memories go stale and have no transactional invariants. Memory only opt-in preference; retrieval indexed policy if sufficiently large.
ADR-006 Deterministic constraints before effects, human approvals. Accepted. Against model acting directly: model outputs can be wrong or injected; no model safety certification, partner credentials or checkout authority.
ADR-007 Mock integration adapters before external provider permission. Accepted. Swiggy officially published MCP interface and approved builder program, but this project has no verified developer access. No implied Blinkit/Zepto/Zomato integration. All demo partner details fictitious and labeled.
ADR-008 BigQuery and evaluation telemetry for impact, not UI-estimated CO2e. Accepted. Against generated credits: physical edible kilograms/safe deliveries/processed organics need actual measurement, baseline and counterfactual.
ADR-009 BigQuery ML forecasting optional only for kitchen with real sufficient timeseries. Against Gemini estimating attendance: deterministic and statistical forecasting may be better, needs backtest.
ADR-010 RAG/Agent Search policy corpus optional vs 5–20 versioned hard rule tables. Simple tables safer/faster until corpus warrants RAG; cite guidance but human eligibility review required.
ADR-011 Cloud Workflows/Tasks/PubSub for authenticated partner long-running requests only; no event mesh for a toy demo. Simplifies retries, reduces accidental duplicate purchases/pickups.
ADR-012 Ray, Earth Engine, video generation, custom training deferred. They are real Google tech but no current size/geospatial/labeled data justifies them. Would increase cost/environmental impact without proven user value.
ADR-013 Firebase App Check, IAM/Secret Manager, Cloud Logging redaction, provider token vault; security not outsourced to model or MCP. Actual IAM and terms to verify.
ADR-014 Google Cloud services only for AI/deployment; external commerce/NGO services as authorized business endpoints. Avoid third-party AI model hosting. Test third-party libraries and terms. Browser itself runs standard open web tech.


PROPOSED COMPONENT DEPLOYMENT
Hosting: Firebase Hosting SPA with per-environment config (dev/demo/prod). UI routes /demo, /household, /kitchen, /recovery, /organics-research, /evaluation, /settings. Firebase Auth via email/Google login if eligible; client receives short-lived token to Cloud Run. Backend FastAPI/Python or Node TypeScript on Cloud Run; choose Python to align ADK libraries, typed Pydantic schemas and testing. AI orchestrator ADK running in Cloud Run initially; Agent Runtime optional where project quotas/region permit. Gemini APIs on Vertex/Agent Platform server auth. Firestore collections tenants, memberships, inventory_observations, meal_events, kitchen_batches, food_offers, recovery_acceptances, organic_loads, action_proposals, outcomes, audit_events; each with owner/actor, trusted_source, source_time, confirmed_time, version, status, tenant and retention policy. Buckets: private opt-in media. BigQuery aggregate benchmark, action trace + deidentified outcome tables. Policies: versioned FSSAI rules and recipient acceptance constraints; regulatory interpretation needs knowledgeable staff validation.
Partner interface: AdapterCapabilities(discover,search,draft,approve,execute,status). Default disabled true for real action; MockAdapter returns DEMO simulated tool event; when real MCP verified connect via ADK with OAuth/IAM, scoped token, expiring approval and price/recipient checks. No stored secrets in browser or prompts.


API, AUTH & EVENTS
POST /v1/intake/parse: upload token/source ref → typed candidate extraction, no commit. POST /v1/facts/confirm: authenticated actor confirms inventory/attendance/batch facts; optimistic version and tenant check. POST /v1/decisions/evaluate: GET verified facts and model options with rule checks; returns assumptions, evidence and alert. POST /v1/actions/preview: draft only, expiration timestamp, inputs and idempotency id. POST /v1/actions/{id}/approve: user authorization based on valid role and unchanged immutable preview; P0 only updates demo outcome, no live provider tool. POST /v1/outcomes: append measured event with measurement method and category. GET /v1/evaluation: role-restricted aggregations. DELETE /v1/account/context: delete per policy and statutory retention. Invalid cross-tenant ID forbidden. Keep source of truth separate from display and agent memory.
Events: intake.created, facts.confirmed, meal.changed, kitchen.cutoff.reached, recovery.offered, recovery.eligibility.needs_review, recovery.accepted, organic.load.received, measured.waste.logged, action.approved. Do not fan out PubSub until real concurrency; start single event table plus bounded worker. Every auto retry checks idempotence and stage.


SECURITY, MISUSE AND SELF-HEALING TRADEOFF
Threats: malicious text in uploaded receipt/NGO form instructs agent to buy or leak schedules; falsified temperature; reused expired offer; household role tracking; prompt injection in search corpus; model confuses grams/ml; volunteer handling of minors or patients; duplicate retry charges. Mitigations: untrusted input labeling; Pydantic schemas and backend allowlisted tools; human review; no unsafe food claims; no patient/child data P0; authenticated tenancy; Firebase rules and Cloud IAM; Cloud Storage signed access/TTL; App Check, Secret Manager, rate limit; Cloud Logging redaction; signed operator evidence; simulation adversarial cases. Model Armor conditional additional control, not trust substitute.
Self-healing means bounded deterministic fallback, explicit paused/error state, retries only idempotent operations and human escalation, not agents automatically editing safety policies. Agent simulation/evaluation and versioned prompt improvements require approved release; never online-train off personal records silently.


NONFUNCTIONAL TARGETS (HYPOTHESIS UNTIL TEST)
Usable at 360px viewport to widescreen with keyboard support and readable contrast; HTTPS; component failure fallback to text/manual inputs. No numeric p95 latency/uptime claim prior to benchmark; track p50/p95, agent token count, request-level cost and trace. Initial quota and cost budget must be explicitly approved. Data minimization and deletion, tenant isolation red-team tests, fake partner watermark; accessible form controls, screen reader labels, consent to notifications and telemetry. Out-of-scope initial offline sensitive data; no Web Push dependency. Environmental AI overhead measure cloud billing/service estimate, do not infer per-query litres.
