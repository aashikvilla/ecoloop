# Architecture knowledge
16 October 2026 — current authority: [household specification](../planning/CURRENT_MVP_SPEC.md), sections 4–7. Household browser demo and secure FastAPI/Firestore groundwork are implemented. Cloud deployment and managed-service behavior remain unproved.

Planned: Next.js/App Hosting; FastAPI/Cloud Run canonical authority; real Gemini and one ADK orchestrator; managed Sessions and consented Memory Bank; preferred managed Runtime. Fallback needs concrete blocker and equivalent proof. Firestore owns confirmed facts/actions/outcomes; memory stores approved preferences. Five typed cards. Private owner-recorded sharing log; real community/commerce operations deferred.

Current implementation: Next.js 16.4.1, React, Tailwind v4. Home, Kitchen, Ask, Shop, Activity, and Settings no longer consume the synthetic browser store. The four destinations use a shared tab-scoped Firebase identity/household selection and canonical Kitchen, Shop, Activity, or assistant endpoints; unauthenticated, empty, unavailable, and error states are explicit. A separate `/account` route retains reviewed household reads and command controls, default-off for writes. Capture draft, item detail, and sharing subroutes report unavailable rather than reading or writing synthetic records. Managed preference controls are also unavailable. Five fixed assistant card schemas remain available for validating backend responses; proposal approval is not connected. A shared bounded allowlisted transport never automatically retries writes. Identity/household changes cancel requests and scope-keyed data prevents previous-household records being displayed during a switch. Live connectivity remains unverified. FastAPI verifies Firebase identity plus explicit active household membership; scoped Firestore transactions include version checks, actor-bound idempotency and payload fingerprints. Owner-private share logs and activity APIs add atomic handover outcomes, scoped pagination and household-timezone expiry checks. Client Firestore/Storage rules deny access by default. See backend-foundation.md, the second-wave implementation notes and latest session for exact limitations.

The broad operator platform and dark cockpit are outside the current household scope. Do not revive unsupported safety/carbon constants or unsubstantiated benchmarks.


Frontend foundation: Tailwind CSS v4 `@theme` in `frontend/src/app/globals.css` is the single semantic design-token source. `frontend/src/components/ui/` contains shared primitives; `frontend/src/components/layout/` contains shared navigation/page shell. Build mobile-first from 360px. No frontend/backend unit tests; use evidence from allowed integration, security, accessibility and end-to-end checks instead.
