# Architecture knowledge
17 October 2026 — current authority: [household specification](../planning/CURRENT_MVP_SPEC.md), sections 4–7. Canonical API reads back the household destinations; synthetic sign-in, membership denial, household creation/readback and sign-out have live evidence. Deployment and complete product acceptance remain unproved.

Planned: Next.js/App Hosting; FastAPI/Cloud Run canonical authority; real Gemini and one ADK orchestrator; managed Sessions and consented Memory Bank; preferred managed Runtime. Fallback needs concrete blocker and equivalent proof. Firestore owns confirmed facts/actions/outcomes; memory stores approved preferences. Five typed cards. Private owner-recorded sharing log; real community/commerce operations deferred.

Current implementation: Next.js 16.4.1, React, Tailwind v4. Home, Kitchen, Ask, Shop, Activity, and Settings no longer consume the synthetic browser store. The four destinations use a shared tab-scoped Firebase identity/household selection and canonical Kitchen, Shop, Activity, or assistant endpoints; unauthenticated, empty, unavailable, and error states are explicit. A separate `/account` route provides household reads, manual facts, shopping commands, actual-outcome recording, owner-reported private sharing and paginated private history. All browser writes share the default-off `NEXT_PUBLIC_ECOLOOP_ENABLE_COMMANDS` gate. `/kitchen/add` now supports manual and bounded text intake into creator-private, unconfirmed candidate records under the authenticated household; candidates do not change canonical Kitchen facts. Kitchen item detail includes a default-off, versioned correction form; its authenticated write path has not had live acceptance. Photo extraction and private media upload remain unimplemented, with Storage rules denying object access. Managed preference controls are also unavailable. Five fixed assistant card schemas remain available for validating backend responses; proposal approval is not connected. A shared bounded allowlisted transport never automatically retries writes. Identity/household changes cancel requests and scope-keyed data prevents previous-household records being displayed during a switch. FastAPI verifies Firebase identity plus explicit active household membership; scoped Firestore transactions include version checks, actor-bound idempotency and payload fingerprints. Owner-private share logs and activity APIs add atomic handover outcomes, scoped pagination and household-timezone expiry checks. Client Firestore/Storage rules deny access by default. Backend settings can load ignored `backend/.env`, but provider calls remain explicitly disabled unless `AGENT_ENABLED=true`; health reports configuration only and does not probe providers. Assistant uses temporary in-process ADK sessions; managed Sessions, Memory Bank and managed Runtime are not implemented or verified. The single ADK agent now has authenticated, household-scoped read-only pantry and active-shopping tools; each tool rechecks current membership and session scope is supplied by the verified API principal. The local-actions branch adds contextual versioned outcome/share flows and Shop add/update/archive commands; archive route registration and live acceptance remain with the integrator. See backend-foundation.md, the second-wave implementation notes and latest session for exact limitations.

The broad operator platform and dark cockpit are outside the current household scope. Do not revive unsupported safety/carbon constants or unsubstantiated benchmarks.

Latest runtime audit: [17 October agent/GenUI review](../implementation/feature-genui-audit-2026-10-17.md). Coding subagents are development workers. The product currently has one ADK agent/Runner without executable ADK tools or runtime subagents; five fixed validated React card renderers are wired to Ask, with approval disabled. Managed Sessions/Memory Bank and proposal persistence remain missing. Latest provider and deployment observations are in the [AI/Cloud Run session](sessions/2026-10-17-ai-cloud-run-review.md); item correction and current local health are in the [item-correction session](sessions/2026-10-17-item-correction.md), and branch-level contextual action work is in the [latest local-actions session](sessions/2026-10-17-contextual-local-actions.md).


Frontend foundation: Tailwind CSS v4 `@theme` in `frontend/src/app/globals.css` is the single semantic design-token source. `frontend/src/components/ui/` contains shared primitives; `frontend/src/components/layout/` contains shared navigation/page shell. Build mobile-first from 360px. No frontend/backend unit tests; use evidence from allowed integration, security, accessibility and end-to-end checks instead.

Latest ADK tool slice: [authenticated pantry and active shopping reads](sessions/2026-10-17-adk-read-tools.md). Managed Sessions/Memory Bank/Runtime and live tool-call acceptance remain unverified.

Activity now summarizes fetched outcome records and owner-private share offers from canonical APIs. It adds only measured quantities sharing the same recorded unit, reports estimated and unknown observations separately, and labels totals as summaries of the loaded page. It does not calculate a composite sustainability score or claim waste prevented/environmental savings.
