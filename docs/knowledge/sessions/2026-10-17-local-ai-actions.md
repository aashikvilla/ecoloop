# Local assistant proposal actions — 17 October 2026

Scope: an isolated local demo branch adds a durable server receipt for validated Gemini/ADK responses, private recent turn history, and explicit proposal actions. The actionable slice is a `BuyCheck` with `ADD`: approval creates one shopping list entry with unknown quantity. Dismissal records a closed proposal. Neither action purchases food, changes Kitchen stock, or records consumption. Other cards remain advice with dismissal only.

The new authenticated routes are `POST /api/v1/assistant/proposals/turns`, `GET /api/v1/assistant/proposals/history`, and `POST /api/v1/assistant/proposals/{proposal_id}/actions`. The router registration and canonical frontend transport allowlist are integration hooks owned by the root branch. Assistant output is saved only after the server assigns proposal IDs and an expiry, checks active membership, and writes the turn and receipts in one Firestore transaction. Turns live below `households/{household}/assistant_users/{uid}/turns`; proposal receipts remain actor bound. Action transactions recheck membership, actor, version, expiry, card type/action, and retry key before writing a shopping entry and resolution atomically.

Evidence in the isolated branch: six targeted Python unit tests passed for an approved add, private creator access, inactive membership denial, stale version, retry replay, and server assigned IDs. ESLint passed on the changed frontend files. TypeScript reported only three unresolved resource names while the shared canonical transport allowlist remains outside this branch. No provider call, Firestore write, or browser acceptance was run here.
