﻿ECOLOOP AI — GOOGLE AI CAPABILITY ATLAS & ARCHITECTURE DECISION RECORD
Research/design v1.0 | 15 October 2026 | Based on Google's official developer/cloud documentation checked 15 Oct 2026. Platform capability ≠ enabled in user's project ≠ user access or prototype test. Google-only inference, infrastructure and managed services. External business endpoints require independently verified partner approval. NO final product selected.


1. EXECUTIVE DECISION
Use Google's AI stack to demonstrate one repeatable, high-consequence decision with auditable inputs and a genuinely necessary AI step. Do not stack service names for points. Google introduced Gemini Enterprise Agent Platform on 22 Apr 2026 as evolution of Vertex AI across Build, Scale, Govern, Optimize; official hackathon track suggests Gemini/Vertex, BigQuery, predictive Vertex AI, Earth Engine, Cloud Storage, Vision AI, Cloud Run and Pub/Sub as suggestions, not a mandatory checklist. Candidate prototypes: (A) changed household meal/shopping, (B) attendance and kitchen waste, (C) safe eligible NGO handoff. Apartment organics, cooling and AI compute environmental intensity remain challenger/expansion branches. Current Google project console link: https://console.cloud.google.com/agent-platform/overview?project=project-7eb2c8c6-27da-46d0-827 . API enablement, model list, quotas, budget and region NOT CHECKED.
HIGH CONFIDENCE INITIAL TECH CORE: one fast available Gemini text/multimodal model + structured output/function calling; ADK as tool/workflow orchestrator; Cloud Run typed policy tools; Firestore source of truth, Firebase/Auth; Cloud Storage for permitted evidence; BigQuery for evaluation; agent evaluation with baseline and error simulation. CONDITIONAL: RAG Engine for genuine document corpus, Workflows for long-running human approvals, Maps/Routes for verified partners, TimesFM for substantive historical forecasting, Memory Bank for opt-in preferences. DEFER: Ray, Earth Engine, model tuning/custom ML, multi-agent fleets, costly spatial/speech/video methods until empirical need.


2. GEMINI MODEL AND PERCEPTION CATALOG — FIT FOR TASK, NOT LATEST NAME
Gemini reasoning models (Pro-class) handle complex multi-step ambiguous context and tool planning. Flash-class handles high-volume extraction/short decisions; Flash-Lite where accessible handles lightweight repeated operations with lower expected cost. Do NOT hardcode a model/version as universally available in Oct 2026; verify Agent Platform models/region and preview status. Gemini 3.1 Pro preview and Gemini 3 Flash were documented by 2026; official live model lists can reflect later updates and should not imply project access. Test cost, latency, extraction and wrong-tool actions head-to-head.
Multimodal input: text/PDF/photos/audio/video. For photos/receipts/meal notes let Gemini extract candidate product/quantity/date/label and quote source; user confirms. Video only if it uniquely captures the operational event (e.g. weigh station) and rights permit; do NOT infer bacterial contamination, true fridge inventory or food-safety eligibility from images. Gemini Live audio streaming and speech models (Chirp STT v2, Text-to-Speech) may help multilingual cooks and waste workers with hands-busy speech interfaces, but compare to ordinary form/voice transcription first. Vision AI/Cloud Vision offers cheaper dedicated OCR/image tagging; Document AI has invoice/expense/layout processors but India grocery receipt language coverage and line item quality need benchmark. Image generation/Imagen/Gemini image/Nano Banana for illustrative UI not core saved-waste output; Veo/video generation, Lyria/music generation irrelevant to resource decision efficacy.
Specialized embeddings: Gemini Embedding models provide semantic similarity/retrieval; not authoritative knowledge; use only if term variations or unstructured docs justify. Model context caching reduces repeated prompt context cost/latency for common stable instructions/corpora, never treats stale food data as up to date. Code execution in model sandbox can help data analysis but business quantities and permissions must be deterministic Cloud Run tools, not self-generated unreviewed code.

3. TOOL USE, AGENTS, MCP, A2A AND GOOGLED AUTOMATION
FUNCTION CALLING: Gemini returns proposed structured tool invocation; an authorized application invokes the tool. No implicit rights to external services. Strict server-side verification of actor, role, record, price, inventory state, allowed tools, consent and approval. Google ADK supports code-first agents, sequential/parallel/loop and graph-style workflows; default a SINGLE orchestrator with typed Cloud Run functions; split only when distinct agents improve evaluation. Agent Studio is low-code alternative; Agent Garden templates can accelerate setup; Managed Agents API supports config-first agents with sandboxed code but availability/price must be checked.
MCP is a tool interoperability protocol, not a partner contract or a magic integration. ADK has MCP clients/tools; Gemini interactions API documentation describes direct remote MCP in supported models/interfaces (Streamable HTTP); determine exact compatibility on chosen Vertex/Agent Platform model. Swiggy's official Jan 27 2026 MCP launch demonstrates conversational shopping via supported clients, NOT proof our app can access it, that its checkout MCP is public, or that Blinkit/Zepto/Zomato have matching access. Use a MockPartnerAdapter contract with preview cart, explicit customer confirm, audit. Connect actual remote MCP ONLY after official developer terms, scopes, authentication, test environment and user authorization. A2A is for agent-to-agent interoperability where multiple owners and authenticated agents truly exist; not needed for 3 mock stakeholders.
Agent Platform Agent Registry inventories MCP/tools/agents/skills; Agent Identity provides least-privilege machine identity; Agent Gateway manages tool and API boundaries; Model Armor screens prompt injection/data exfiltration. These controls matter particularly where a malicious receipt/restaurant note could cause undesired orders or NGO assignments.
Cloud Workflows is deterministic durable service orchestration with waiting/retries/callbacks; use for NGO donor approval/pickup chain if real partner flow, not as a replacement for reasoning. Cloud Tasks for individually scheduled/retried requests, Pub/Sub for events/fanout, Eventarc for cloud event triggers, Cloud Scheduler for recurring jobs; Application Integration/Integration Connectors for existing authorized enterprise SaaS interfaces. All are NOT generative AI themselves. Need idempotency/dead-letter/error handling and no retry of purchase without safeguards.

4. KNOWLEDGE BASE VS STATE VS MEMORY — A CRITICAL THREE-WAY SPLIT
AUTHORITATIVE STATE: Firestore stores user-confirmed dated pantry quantities, actor approvals, organization acceptance, tool audit and actual weighed waste; query exact keys, amounts, versions and timestamps. Do NOT use semantic retrieval or generated memories to answer 'how many tomatoes are present'.
KNOWLEDGE: RAG Engine is managed document indexing/retrieval for approved FSSAI/municipal handling guidance, NGO receiving policies, facility manuals, citation-ready climate/food references. Agent Search provides search across documents/websites/structured authorized data and enterprise connectors; Vector Search / Spanner-managed vector databases can support embeddings/semantic retrieval where collection large. Small 5–20 fixed policy documents can be stored as versioned rule tables and ordinary document links instead; RAG is unnecessary until task complexity passes baseline. Google Search grounding is for public, changing information; Maps grounding/Places for available place facts, never evidence a charity actually accepts a donation.
PREFERENCE MEMORY: Agent Platform Sessions for conversation; Memory Bank can store user-consented persistent preferences (diet preferences, chosen shopping channels, accessible speech language), with review/delete controls and no covert household surveillance. Never silently treat memory about food stock, expiry or recipient acceptance as current truth. Data lineage: which document, effective date, authorship, freshness, rules version, actor confirmation, retrieval score and uncertainty.
Sources: https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/rag-overview ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/vertex-ai-search ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/vector-db-choices ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/overview


5. PREDICTIVE AI AND BIGQUERY AI — WHERE LLM IS NOT THE BEST ESTIMATOR
BigQuery/BigQuery ML support SQL analytics and trained time-series forecasts (ARIMA_PLUS/ARIMA_PLUS_XREG), built-in TimesFM foundation time-series through AI.FORECAST, anomaly detection, AI.CLASSIFY and LLM functions for large-scale extraction/classification. Use for institution attendance / amount prepared, household segment patterns only with REAL representative enough historic observations, operator collection volumes and cooling load. Forecasts require relevant covariates, date cutoffs, enough history, backtesting and error metrics; avoid inferring a causal reduction from better forecast alone. A canteen's 7-day synthetic table cannot validate production prediction.
Vertex/Agent Platform AutoML and custom training handle classification, defect/object detection and specialized ML with labeled data. BigQuery ML first if the data lives in BigQuery and the problem is a simple forecast; Ray distributed Python execution for large training/preprocessing only when data volume or distributed evaluation proves need. Ray clusters can remain running and bill resources; an extra long-lived compute cluster undermines environmental efficiency for tiny hackathon workloads. Dataflow/Apache Beam for sustained massive batch/stream processing; unnecessary for few receipts/case logs.
Source: https://docs.cloud.google.com/bigquery/docs/forecasting-overview ; https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/bigqueryml-syntax-ai-forecast ; https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/bigqueryml-syntax-ai-classify ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/training-overview ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/open-source/ray ; https://docs.cloud.google.com/dataflow/docs/concepts/beam-programming-model


6. GEOSPATIAL & ENVIRONMENT DATA — A REAL BROWNIE-POINT OPTION IF GROUNDED
Google Earth Engine provides large satellite/raster geospatial datasets and cloud-scale analysis for crop patterns/vegetation, thermal exposure, watershed stress proxies, urban heat, land cover, flood/forest monitoring. It does NOT know fridge contents, municipal waste operator capacity, safe pickup availability, household electricity savings or precise water quality without independent data. Use only for farm/postharvest/climate-risk hypothesis with an observed actionable remote-sensing gap and appropriate resolution; otherwise no need for P0 food household/kitchen.
Google Maps Platform Places/Routes/Route Optimization can locate consented authorized operators and plan pickups, subject to actual data rights, dynamic availability and local material acceptance; distance alone does not guarantee cold chain or permit. Maps Environment APIs offer Air Quality, Pollen, Solar and Weather data, with explicit geography/coverage and sampling model limitations; for future air-quality/energy/cooling context, not generic 'AI saves the planet' claims. BigQuery geospatial joins and Earth Engine interop enable regional aggregation; outputs require units/resolution.
Source: https://cloud.google.com/earth-engine ; https://developers.google.com/maps/environment ; https://developers.google.com/maps/apis-by-platform ; https://developers.google.com/maps/documentation/air-quality


7. SELF-HEALING, IMPROVING AGENTS AND RELIABILITY — WHAT IS REAL
Automatic retry/recovery is NOT autonomous learning. BUILD SELF-RECOVERING EXECUTION: Cloud Workflows explicit state, bounded retries with exponential backoff, timeout, fallback, compensation, idempotency, circuit breakers and human escalation; never retry an irreversible order or food pickup blindly. Model fallback: Flash→Pro for uncertain extraction/complexity with cost cap, or deterministic/manual mode where needed. Tool provenance and versioned canonical state limit wrong decisions; prompt-injection defense on untrusted receipts/messages with Model Armor + typed tools/approval.
LEARN FROM EVIDENCE, NOT EVERY USER MESSAGE: Agent Platform agent simulation generates multi-turn synthetic tests and tool fault scenarios; Agent Evaluation measures whole trajectories and failures; Agent Observability collects logs/traces; prompt optimizer/Agent Optimizer may propose improved instructions/tools after clustering failures. Changes should go to versioned candidate → held-out gold tests → reviewer approval → controlled rollout / rollback, never silently self-edit policy/food safety or grant new permissions. Fine-tuning Gemini supported for specific models if there is licensed annotated representative data, validated gain vs prompting and proper evaluation; NOT essential in one-week demo. Agent anomaly/threat detection is security monitoring, not proof of correctness.
Models cannot 'learn real food safety' from feedback without verified labels, robust experiments, safety policy and deployment oversight.

8. GOOGLE CLIENT, DEPLOYMENT, SECURITY AND FOOTPRINT
UI: Flutter mobile/web or Firebase Hosting web; identity Firebase Auth + App Check. Firebase AI Logic supports client Gemini and App Check but complex permissioned agent and merchant control should run server-side on Cloud Run/Agent Runtime, not in mobile client. Genkit (Google open-source full stack AI flows) overlaps with ADK and may be an alternative for TypeScript developers; avoid both frameworks unless boundaries clear. State Firestore; Cloud Storage receipts/media with consent and expiry; Cloud Logging/Monitoring, Secret Manager, IAM/KMS; BigQuery de-identified evaluation. Pub/Sub/Cloud Tasks/Workflows only when asynchronous multi-party workflow really exists. Cloud Carbon Footprint provides service/project estimate, NOT trusted per-prompt water footprint or 'CO2 saved' credit. Right-size and cache AI calls; track inference counts and compare to measured environmental effect.
Sources: https://firebase.google.com/docs/ai-logic/production-checklist ; https://firebase.google.com/docs/genkit ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/overview ; https://docs.cloud.google.com/carbon-footprint/docs/methodology


9. OPPORTUNITY-TO-TECH CROSSWALK (POTENTIAL, NOT SHIPPED)
A Household changing plans / quick-commerce: FIRST capture Gemini text/photo/receipt (maybe voice) and strict structured JSON; Firestore state+permission/versioning; ADK tool calling to deterministic portion/duplicate calculation; optional RAG for source-backed label/storage instructions; Cloud Run approval/action preview; BigQuery measures extracted case accuracy, time and weighed edible waste. MCP/merchant cart only authorized conditional. In one-week demo, one agent plus typed tools beats a huge fleet of specialized agents unless eval proves otherwise. Kill if WhatsApp/shared list/NoWaste/Samsung Food or ordinary Gemini equally good.
B Institutional kitchen: Gemini unstructured note/roster/attendance extraction; BigQuery SQL or optional TimesFM forecast IF site data; Cloud Run cutoff/portion/diet rules; chef approval; BigQuery verified prep/surplus/plate kg; optional Cloud Workflows to wait for approval. Kill if QR headcount or Winnow/Leanpath better.
C Safe surplus NGO: Gemini donor description normalization (NEVER model food-safety certification); versioned FSSAI and partner rules in RAG/rule tables; deterministic human eligibility; Workflows safe offer→review→capacity→pickup→acceptance; Google Maps distances when capacity true; multi-tenant recipient and NGO portal; signed quantity/temperature/logs. No consumer auto-donation. Kill if vans/cold chain/recipient eligibility or structured Google Form are dominant.
D Apartment wet waste: correct local source segregation, Google Forms or app collection event, RWA/collector/operator accept/reject, measured processed wet kg, contamination and compost output. Simple sign/bin/manual WhatsApp is baseline; Gemini multilingual guidance only if low literacy/language/document heterogeneity genuinely matters. Strong physical-operational constraints.
E Air/water/cooling/building: future Earth Engine + Maps environment/weather + verified sensor/bill + BigQuery time series + Gemini explanation if information processing is bottleneck. No sensor→no factual resource saving.
F AI infrastructure: BigQuery billing, Google Cloud Carbon Footprint, Cloud Monitoring/cost, model router/cache and right-sized tiers; compare useful output quality per compute/emissions. Water attributed to AI tasks not independently measured at current task granularity.
Google-only rule: use Google's models/API/runtime, Firebase/Flutter and approved Google Cloud services; external vendors are authorized data/action endpoints, not underlying AI hosting.


10. BUILD PHASES AND EVALUATION GATES
Phase 0: inspect live model list, API quotas, billing, region, pricing, IAM and compatibility in specified GCP project; source/legal license checks. NO actual project access yet.
Phase 1: 12–20 gold cases each A/B/C with clearly labeled simulated records, candidate vs baselines (Google Forms/Sheets+rules, ordinary Gemini, incumbent). Tests of tool sequence, state reconciliation, safety and user effort. Do NOT call them measured environmental effects.
Phase 2: common server/API + Gemini extraction + Firestore verified facts + ADK tool + approval + audit + evaluation report. Deploy one functional end-to-end workflow per candidate; avoid overbuilding.
Phase 3: compare true operational partner access and differentiated measurable failure; select ONE main prototype if sufficient evidence. Preserve fatal rejection reasons and unknowns.
Phase 4: optionally add RAG, Memory Bank, Workflows, Model Armor/Gateway, BigQuery TimesFM or real MCP only when incremental quality, consent and data gates passed. Ray/Earth Engine only when large-scale or geospatial opportunity genuinely requires.
Success: correct decisions vs baselines, tool trajectory quality, permissions and zero unsafe donation/auto-order, user steps/time, p95 latency, marginal AI cost and low environmental overhead. Physical outcomes only from actual weighed waste / accepted safe recovery / processed wet mass.
Official competition rubric: technical merit/GenAI 40%, problem alignment/impact 25%, innovation 25%, UX 10%. Maintain independent 100-point Problem Value Score and never convert a stack diagram into impact evidence.
