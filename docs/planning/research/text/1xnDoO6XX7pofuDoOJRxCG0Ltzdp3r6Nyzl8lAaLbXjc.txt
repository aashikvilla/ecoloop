﻿ECOLOOP AI — THREE GOOGLE-ONLY PROTOTYPES, COMMON BENCHMARK & IMPLEMENTATION BACKLOG
Version 0.2 | 15 October 2026 | DESIGN SPECIFICATION; no actual prototype experiments run. Use Google Cloud + Gemini only; human approval, no live food-safety judgements or unsupported impact claims.


1. COMMON EXPERIMENT DESIGN
Goal: compare three candidate core workflows FAIRLY, not pick whichever is visually impressive. A=household changing plans; B=small institutional kitchen late meal changes; C=eligible safe surplus donor-to-recipient handoff. Each has different impact units; normalize evidence, not raw kilogram scale. Stages: documentary desk validation → 12–20 reproducible gold scenarios per lane → comparator test → permissioned real artifacts → conditional 2–4 week physically measured field test. No claimed achieved results.
Common technical baseline 0: Google Sheets/Forms/Calendar + rule-based calculator, reminders and human coordination. Baseline 1: ordinary Gemini text chat given identical authorized information. Baseline 2: current incumbent workflow or published features where genuine product access available (NoWaste, Samsung Food; Winnow/Leanpath/SmartQ; NGO WhatsApp/IFSA/structured intake). Candidate: structured Gemini + Google ADK + Firestore canonical state, optional verified tools and approvals. Compare equivalent inputs, timing, evidence availability, skill and permissions, not advantaged agent access.
Pre-register correctness, manual effort/minutes, clarification count, severe safety/permission errors, task completion, model/token cost, p95 latency, fraction of outcome actually measured, false confidence and user retention. Evaluate quality blinded where possible. DO NOT invent a statistical power claim; 12–20 scripted cases test technical feasibility only.
Fatal gates for every lane: unsupported problem prevalence, no recurring avoidable operational failure after alternatives, unsafe recommendation, missing right to use data, absent action authority, inability to demonstrate core behavior, or only fictional kg/CO2e benefits. Problem Value Score /100 withheld pending unmet gap; judges' 40% AI merit,25% impact,25% innovation,10% UX separate and uns cored.


2. PROTOTYPE A — HOUSEHOLD FOOD DECISION / QUICK COMMERCE
Persona: shopper, cook, secondary independent purchaser, diner. Existing substitute: shopping list/WhatsApp, NoWaste, Samsung Food, ordinary Gemini, use-first shelf and non-AI behavior change. Real question: when two people cancel dinner or an Instamart order arrives with substitutions, are portions and purchases adjusted before avoidable edible disposal? Input: a household-owned sample grocery receipt or manually confirmed pantry + schedule change; no background surveillance. Process: Gemini structures observations, user confirms; Firestore records timestamps, members' permissions, actual vs claimed quantity; ADK tool retrieves trusted state; deterministic servings/availability/units; Gemini explains 2 feasible plans; user confirms a change; impact journal accepts weighed waste. MCP branch: official Swiggy Jan 27 2026 announcement supports Swiggy/Instamart conversational MCP, but OUR credentials, scopes, permitted developer use, checkout rights and service availability not verified. Preview-only adapter until authorized. Do not assert all platforms share APIs.
Gold cases A01 dinner cancellation, A02 duplicate milk already consumed, A03 mismatched receipt quantities, A04 substitutions and partial delivery, A05 fixed packs vs loose market produce, A06 two owners disagree on stock, A07 time-stale leftovers, A08 discount-filler cart, A09 dietary preference mismatch, A10 ambiguous Hindi/English voice, A11 opt-out household member, A12 unsafely stored food must not be declared edible. Extend to 20 adversarial cases. Outcome proxy: correct changes and effort, NOT kilograms saved. Field outcome: physically measured avoidable edible grams per household-week and kg per purchased edible kg; compare matched/rand baselines if feasible, include purchases/returns/delivery packaging and displacement.
Google backlog: A1 Firebase Auth, household memberships, consent (P0); A2 Firestore event and inventory-state schema (P0); A3 Cloud Storage/Gemini receipt + voice/text candidate extraction and annotation (P0); A4 deterministic quantity/calculator and contradiction checking in Cloud Run (P0); A5 ADK decision coordinator and Google grounding with approved resources (P0); A6 explicit cart draft approval (P0 simulated); A7 optional MCP test harness with NO live call until authorization (P1); A8 kg outcome logging/BigQuery dashboard (P0); A9 evaluation gold cases and cost/latency reports (P0).
Kill A if shared message, a fridge organizer or basic Gemini solves the disruption at lower effort; inventory maintenance may be more costly than savings. Quick-commerce PURCHASE RATE ≠ physical waste; small top-ups can REDUCE excess buying.


3. PROTOTYPE B — SCHOOL/OFFICE/HOSPITAL KITCHEN EXCEPTION COORDINATION
Persona: head chef, canteen manager, meal subscriber/attendance coordinator, person verifying quantities. Existing substitute: attendance headcounts, QR opt-in, menu planning, kitchen spreadsheets, non-AI signage, Winnow, Leanpath, Orbisk/SmartQ and hospital diet systems. Research findings: Beijing workplace physically measured 78.8 g lunch plate waste/diner (n=656 study); Australia hospital recorded 117.5 kg/day unserved food at one site, preventable component unknown; Vietnam school study weighed 1,720 lunches (~85 g discarded per lunch). Multiple non-AI studies have measurable effects, so generic tracking and forecasting are not unique.
Input: anonymized Google Sheets rosters + menu + supply + chef notes, 14–28 days in a real pilot only if permissioned; no patient clinical identifiers. Process: Gemini structures late text/voice event; deterministic versioned cutoff/portion rules and optional BigQuery ML forecast if dataset large enough; decision proposal before cooking cutoff; chef accepts, overrides or rejects; measured preparation/untouched surplus/plate waste separately. Food safety/allergy and clinical menu changes remain qualified human authority.
Gold cases B01 30 absent students, B02 last-minute group event, B03 menu substitution with allergens, B04 supplier shortfall, B05 ward patient change requires clinician authorization, B06 meal cancellation arrives after cooking cutoff, B07 duplicate roster event, B08 false forecast with unchanged attendance, B09 unserved leftovers vs plate scraps, B10 sanitation/temperature gap, B11 staff shift changes, B12 incorrect units. Extend to 20.
Backlog: B1 Google Sheets source adapter/synthetic roster (P0); B2 Firestore kitchen tenant isolation (P0); B3 Gemini note/document extraction (P0); B4 deterministic batch count and safety cutoff (P0); B5 ADK exception coordination (P0); B6 approval UI for chef and food-safety escalation (P0); B7 BigQuery optional baseline forecast only with enough real data (P1); B8 weigh log differentiated by source per meal (P0); B9 compare signage/headcounts/incremental AI (P0).
Kill B if meal headcount and ordinary rules provide similar accuracy; organization already has well-used Winnow/Leanpath; late updates arrive after irreversible prep; no meal / edible-waste measurements.


4. PROTOTYPE C — VERIFIED ELIGIBLE FOOD SURPLUS HANDOFF
Persona: restaurant/dark store/school donor, FSSAI-compliant food recovery coordinator, NGO driver, receiving kitchen or approved institution. Status: PROCESS AUDIT first; do not imply charity eligibility or automatic food-safety certification. Documented competitors: FSSAI IFSA, Robin Hood Army, Feeding India, Goodr in other markets, WhatsApp/phones and NGO dispatch spreadsheets. Observed failed eligible pickup denominator UNKNOWN; existing transport/cold-chain resource may dominate.
Input: DEMO-only batch offered by donor with typed contents, labeling, origin, storage logs, validated timestamps, temperature records, confirmed quantity, human review and recipient capacity. Process: Gemini extracts donor's unstructured details and clarifying questions; rules flag records requiring human safety review (not approve food), deterministic capacity/time windows; propose eligible candidates; coordinator approves and recipient confirms; produce custody audit and actual weighed delivered/accepted amount; report rejected offers and why. Orphanages, care homes, shelters and community kitchens must consent and meet nutrition/food-safety rules. Never auto-assign vulnerable beneficiaries.
Gold cases C01 unopened packaged produce with valid records, C02 already served buffet leftovers (NOT ELIGIBLE), C03 unknown time outside control (ESCALATE), C04 recipient special diet (NO AUTO), C05 volunteer van unavailable, C06 no recipient storage, C07 batch recall after transfer, C08 donation accepted then canceled, C09 donor requests no public identity, C10 falsified temperature record, C11 mixed inedible wet waste, C12 no pickup before handling cutoff. Extend to 20.
Backlog: C1 multi-tenant partner portal for donors/recovery organizations (P0 simulated), C2 validated offer form + Gemini extraction (P0), C3 deterministic documented policy restrictions and human review (P0), C4 capacity and recipient constraints records (P0), C5 Google Maps Platform travel and candidate dispatch simulation with manually entered partner locations (P1), C6 approval/chain-of-custody event log and recall audit (P0), C7 NGO/waste operator accept/reject UI (P0), C8 20–50 observed eligible offers only after verified partner consent (field gate).
Kill C if failure principally comes from lack of cold chain, volunteers, donor safety eligibility, or capacity rather than unstructured information; or if standard intake plus WhatsApp performs equivalently.


5. SIDE-BY-SIDE SCORECARD — NO FABRICATED RESULTS
Comparable technical measures for ALL: structured extraction exactness, task completion, user steps/minutes, time to decision, permissions, avoidable errors, model/tool call count, latency/cost, baseline ranking and audit completeness. Different operational units: A edible g/household-week; B edible g/meal actually served with preparation/plate separated; C eligible offers delivered/offered and verified kg delivered/accepted, not 'meals saved' unverified. Outcome-specific environmental accounting requires net transport, packaging, additional AI energy and location/food-specific factors.
Gate G0 problem observed in intended segment, G1 unmet failure after existing alternatives, G2 authority/data available, G3 Gemini incremental benefit, G4 no safety/privacy violations, G5 physical outcome measurable, G6 reviewer differentiation and usable UI. Every gate = PASS / FAIL / UNKNOWN and cited evidence; UNKNOWN does not count as PASS.
Current facts: A G0 conditional PASS sample-level, G1 unknown; B G0 PASS sample-level, G1 unknown; C G0 structurally serious, G1 eligible-offer failure unknown. None has completed gold case execution. No validated feature ranking, launch authorization or monetization.


6. GOOGLE-ONLY SHARED TECHNICAL PLATFORM
Flutter or Firebase Hosting interface, Firebase Auth, Cloud Run API and deterministic tools, Firestore canonical provenance + versioned events, Cloud Storage media, Gemini on Vertex AI, Google ADK and Agent Platform where provisioned, Google Maps Platform only for verified operations, BigQuery for deidentified evaluations. Agent memory may hold user-approved preferences, NEVER authoritative expiring food inventory. MCP through ADK may connect to external partner server if server, developer permission, authentication and user approval all verified; absence of these means a mock adapter. Simulation cannot claim integration or action.
Current Google project URL supplied but console access/billing/runtime still not tested. Read https://adk.dev/mcp/ and https://www.swiggy.com/corporate/press-release/swiggy-now-lets-you-order-food-dineout-and-shop-on-instamart-directly-inside-chatgpt-and-claude/ .


7. BUILD ORDER AND DECISION POLICY
Build common evaluation harness FIRST; then minimal A, B, C sketches sharing ingestion/schema/tool executor/eval; avoid 3 full applications. Produce a recorded walkthrough per lane with identical coverage: messy input → confirm → reconcile → suggest → human approve → mock action → outcome logging. Run baselines on fixed gold cases. Compare fatal gates and evidence before choosing. Target one chosen workflow for hackathon 3-minute pitch; do not promise a full super-app. Keep 100-point Problem Value and official rubric entirely separate.
Decision backlog: 1 consent/data; 2 Google project access; 3 official commerce MCP developer rights; 4 at least 1 real kitchen/NGO collaborator; 5 physical outcome measurement strategy; 6 threshold for prioritizing; 7 monetization only once valued problem established.
