﻿ECOLOOP AI | SOLUTION MAP, GENAI FIT, AND DECISION GATES v0.1
15 October 2026 | Concept map ONLY, not validation that a product should be built.


1. EVIDENCE-TO-CAPABILITY MATRIX
FOOD-01 household plans diverge after changes | Existing competitors: NoWaste, Samsung Food, shared lists and non-AI gamification. Proposed system hypothesis: consented fact state + temporal change event reconciliation + explanation of options. Gemini role: multilingual natural language/audio/receipt/image parsing and grounded decision explanation; ADK tool orchestration; Memory Bank optional preferences. Deterministic role: units, portions, inventory versioning, approvals. Measurable: avoidable edible kg and effort. Status COMPARATIVE VALIDATION; strongest reject: basic list works equally well.
FOOD-02 cross-channel quick commerce ordering | Competitors: Blinkit/Zepto/Instamart/bbnow + group ordering, stock lists. Proposed system: user-submitted or authorized order observations reconcile stock. Gemini entity matching and product descriptions where needed. Deterministic: SKUs, consent, cart approval, totals. Data unknown. NO inference that q-commerce causes waste. NARROW until matched purchase-disposal cases and permitted provider rights.
FOOD-03 small institutional overproduction | Competitors: Winnow, Leanpath, Orbisk, simple signage/headcount. Proposed hypothesis: unstructured attendance/procurement/roster exception interpretation; forecasting should be rules/BigQuery ML. Gemini role: explanations/exception extraction, perhaps multilingual kitchen notes. Measurable: kg edible overproduction vs kg plate per meal; food quality and cost. NARROW pending real operator records and competitor benchmark.
FOOD-05 safe surplus recovery | Competitors: IFSA/FSSAI, Robin Hood Army, Feeding India, Goodr/Too Good To Go in covered geographies. Proposed hypothesis: agent-assisted offer-intake document normalization + eligibility questions + dispatch proposal, always human controlled. Deterministic: food safety requirements, capacity, travel, time temperature proof, partner eligibility. Measure completed eligible offers and kg actually safely accepted. DEFER until recurring non-logistics residual gap proven; no photo-based food safety.
FOOD-06 farm-to-market perishable chain | Existing logistics, cold storage and agricultural expertise. Gemini role maybe handling messy inspection documentation, but sensor, contract, infrastructure and optimization dominate. No generic crop diagnosis. DEFER till a particular crop/area/stage and real data.
FOOD-07 labels | Government guidance already exists; Gemini transcription/translation of verified label, deterministic rule lookup; reject if authoritative plain guidance enough or unsafe errors.
FOOD-08 compost/segregation | Collection and municipal service physical gap dominates, possible photo classification but not strong GenAI novelty. PARK.


2. AGENTIC SYSTEM BRAINSTORM (UNVALIDATED; NOT REQUIRED ALL AT ONCE)
Agent A Intake Interpreter: Gemini (image/voice/text) to parse observation candidates with provenance and missing fields, schema checks.
Agent B Context Resolver: retrieve confirmed household state, timestamps and meal plans, identify contradictions; Agent Platform Sessions/Memory Bank may help preferences but canonical facts reside in Firestore.
Agent C Decision & Trade-off: Gemini natural language reasoning over constraints and choices; tool calls to deterministic calculators, safety rules, availability only via trusted provider.
Agent D Action Coordinator: create reminders, a reviewable shopping draft and user-authorized tasks; never spend/donate automatically.
Agent E Measurement Auditor: detect unsupported claims and reconcile proposed vs completed vs physically measured outcomes; BigQuery aggregations and server-side calculations, not LLM-generated emission values.
Agent F Future Partner Workflow: document extraction, recovery-eligibility candidate and handoff orchestration for verified partners; distinct auth tenant and human approvals.
Hypothesis: multi-agent may make a demo visually impressive but also raise latency/cost/error. Single ADK orchestrator plus typed tools is default until evidence justifies splitting agents.


3. GOOGLE CLOUD / GEMINI FEATURE FIT
Gemini via Vertex AI: multimodal capture and context, structured outputs, function calling, reasoning and explanation. Gemini Google Search grounding or controlled search API: external context with verified source; never safety oracle.
Agent Development Kit (ADK): workflow control, tools, session state, agent actions with audited boundaries.
Agent Platform (Agent Engine/Runtime): agent deployment/runtime if project API, region and quotas support it; otherwise Cloud Run.
Agent Platform Memory Bank: optional consented long-term user preferences and personalization, but not actual perishable item inventory.
Firestore: source of truth. Cloud Storage: secure opt-in images/receipts. BigQuery: actual measurement/telemetry and model evaluations.
Cloud Run: protected functions/tools. Firebase Authentication + Flutter: Google-only user interface.
Cloud Scheduler/Tasks/PubSub: low-noise opt-in events. Vertex AI GenAI evaluation: exact tool trajectories, error severity and comparison with baselines.
Document AI: only if benchmark finds Gemini extraction insufficient.
BigQuery ML: conventional forecasting if legitimate meal-volume data; Gemini should not be used just to add AI where predictive models excel.
Maps Platform: route/travel where legally allowed; cannot promise timely cold chain.
Google Cloud Carbon Footprint: cloud accounting, not precise per-LLM water accounting; avoid unverified prompt footprints.


4. SOLUTION DECISION TREE / HARD STOPS
Is harm and frequency evidenced? NO→research. Is precise workflow and decision owner identified? NO→narrow. Does existing product/manual workflow solve it? YES→reject unless measurable comparative failure. Are data and rights valid? NO→reframe slice. Is AI needed? NO→use simpler software or reject as GenAI idea. Can errors cause food safety, privacy, money or recipient harm? YES→human approval, deterministic policy and hard stop. Can core idea be demonstrated truthfully with Google tools? NO→defer. Is physical outcome verifiable? NO→don't claim environmental impact. Score only after gates.


5. PROPOSED GOLD BENCHMARK DESIGN (NOT RUN)
Dataset ~20 hand-authored scenarios + real consented records later; cover India shopping, multiple household cultures/languages and conflicting plans. Compare a simple Google Sheets list+rules, ordinary Gemini chat, incumbent current product steps, and ADK structured workflow. Predeclare task correctness, user effort, false confident suggestions, completion, safety violations, cost/latency. Have user/blinded reviewers grade. For environmental effect, need prospective weighed-waste measurement weeks; a 3-minute hackathon demo cannot prove physical impact on its own.


6. ALTERNATIVE PATH: BIGGER SOCIAL IMPACT
If household candidate fails, small school/canteen demand adjustment and FSSAI-safe recovered surplus may provide larger resource savings per participating organization. But they are not simply modules in one prototype; data access, safety, roles and buyer differ. Evaluate side-by-side separately.
Further environmental scope (water/energy) is a product strategy option, not evidence that users want a single sustainability super-app.


7. JUDGE STORY vs REAL DEVELOPMENT
Technical merit 40%: show real Google stack, structured multimodal extraction, grounded sources, safe agent actions and evaluation telemetry; avoid an inflated agent count.
Impact 25%: documented serious edible loss, defined user, measured kg with baseline and counterfactual, plausible climate/household resource savings, no fake CO2.
Innovation 25%: show comparative win on dynamic plan-reconciliation step vs NoWaste/Samsung/normal Gemini/non-AI interventions.
UX 10%: minute-long low-friction path; avoid inventory chores.
If comparable benefit not established, no final winner selected. 100-point Problem Value Score withheld until residual gap and user costs measured.


8. NEXT DESIGN / VALIDATION DECISIONS
A Select one India metro and household vs small kitchen as initial segment (recommended provisional household due consented data access, NOT necessarily higher problem value).
B Establish source-of-truth data input and how much can be maintained without repeated user effort.
C Inspect Agent Platform console for service status, Gemini model, regions, quota and budget; no deployment performed yet.
D Build precisely one gold user journey with a fake checkout, no real external partnerships; compare against normal Gemini and shared list before expanding.
E Keep demo claims explicitly simulated; follow up with primary measured field evaluation if shortlist passes secondary gates.
