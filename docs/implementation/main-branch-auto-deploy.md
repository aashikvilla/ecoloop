# Main branch Cloud Run releases

`.github/workflows/deploy-main.yml` builds immutable frontend and API images from tracked GitHub checkout files when application code lands on `main`. A push deploys tagged no-traffic Cloud Run candidates and checks the account page, API health, unauthenticated API denial, managed-session configuration and exact-origin CORS. Pushes do not promote traffic. After a live authenticated household and organization AI turn are accepted against the exact main candidate, an owner may manually dispatch the workflow with `promote=true`; failed candidate checks leave current traffic in place.

The workflow uses GitHub OIDC and Google Workload Identity Federation. It has no service-account key. The provider condition is restricted to this repository ID, `refs/heads/main`, and this exact workflow path. The deploy service account can publish to the `ecoloop` Artifact Registry repository and deploy Cloud Run using only the web/API runtime identities. Public Firebase Web SDK settings and `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` are stored as repository Actions variables; they are build-time browser configuration and are not private credentials. The server-only `GOOGLE_MAPS_ROUTES_API_KEY` is instead stored as Secret Manager secret `ecoloop-google-maps-routes:1`, with `roles/secretmanager.secretAccessor` granted only to the API runtime service account. The key is API-restricted to `routes.googleapis.com`; it is neither a GitHub variable nor a frontend value. See the [Maps key guide](google-maps-keys.md).

The current demo revision uses Vertex AI and managed ADK Sessions with an application limit of 12 AI requests per user/day. Memory Bank remains disabled because no approved preference acceptance flow is configured; managed Agent Runtime is not deployed. The smoke checks do not prove model response quality; perform the authenticated live-turn acceptance before promotion. The project has an alert-only monthly budget and no verified hard all-services spending ceiling, so keep request volume bounded.

After pushes, inspect **Actions → Deploy EcoLoop to Cloud Run**. A green push run means candidate HTTP/health/auth-boundary smoke checks passed; traffic remains on the existing revision. A green manually dispatched `promote=true` run means the candidate checks passed and the tagged revisions received traffic. To roll back, route traffic to the previously serving revision in Cloud Run; retain its revision name from the service revision history. The workflow keeps every image tagged with its Git commit SHA.

New branches must use a short feature-derived type and name, such as `feature/meal-plans`, `fix/household-create`, or `docs/deploy-guide`; never use a `codex/` prefix.
